Chapter 1

Welcome

Keyboard Curator is a Mac app for changing what your keyboard does: which key sends which character, what happens when you hold a key, how the lights look, and much more.

What you can do with it

  • Rearrange keys. Put any letter, symbol, shortcut or function on any key.
  • Add layers. Give every key a second, third or tenth job, reached by holding or tapping another key.
  • Make keys smarter. A key can be Shift when held and Enter when tapped. It can do one thing on a single tap and another on a double tap. It can type a whole phrase.
  • Set up the trackballs or touchpads built into your keyboard.
  • Color the keys. Give each key its own color on each layer, so the keyboard shows you where things are.
  • Choose and tune the firmware. Pick which firmware a keyboard runs, add extras from the ZMK community, and adjust sleep, Bluetooth, debounce and the rest.
  • Put the result on the keyboard. The app builds firmware and walks you through flashing it, or, on keyboards whose firmware is configured while it runs, writes your layout straight to the keyboard over USB.
  • Try the keyboard out. A key tester lights each key as you press it, and plays a note for it.

Which keyboards

This edition supports four split keyboards:

  • the Cyboard Imprint (wireless), in all nine of its key arrangements, including the full 82-key one, on ZMK or on RMK;
  • the MoErgo Go60, on MoErgo's ZMK or on RMK;
  • the MoErgo Glove80, on MoErgo's ZMK or on RMK;
  • the Dygma Defy (wireless or wired), on Dygma's own firmware.

Chapter 2 explains what ZMK, RMK and Dygma's firmware are; Chapter 15 lists what is particular to each keyboard.

What you need

  • A Mac.
  • One of the supported keyboards and a USB-C data cable.
  • For firmware that is built (ZMK, and RMK on the Imprint): a free GitHub account, and GitHub's command-line tool signed in to it. GitHub's servers are what turn your layout into firmware; Chapter 13 explains this. Keyboards configured while they run, the Defy and the MoErgo boards on RMK, need no GitHub account.
Read this first: how finished is it?

Keyboard Curator is in early development. The parts that turn a layout into ZMK firmware are checked automatically: every kind of configuration the app can produce is compiled with the real ZMK tools. But much of the app has not yet been used on real keyboards by real people, and some firmware it offers has never run on the keyboard it is for.

In practice that means: expect rough edges, save often, and treat the features marked experimental with care: per-key lighting, RMK, and writing to a running keyboard. Where a feature is unproven, this guide says so. Nothing the app does can permanently harm a keyboard; the worst case is flashing the manufacturer's original firmware again, which Chapters 15 and 17 cover.

How to read this guide

If programmable keyboards are new to you, read Chapter 2 first; it explains the ideas everything else builds on. Chapters 3 to 6 get you editing. After that, dip into whichever chapter matches what you want to do, or go straight to the recipes in Chapter 16.

Throughout the guide, names you will see on screen are written like Build Firmware, keys on your Mac's keyboard like ⌘S, and text you would type like &kp A.

Chapter 2

How a programmable keyboard works

A short tour of the ideas behind the app. Ten minutes here will make every other chapter easier.

The keyboard is a small computer

Inside each half of your keyboard is a tiny computer. It runs a program called firmware. The firmware watches the switches, decides what each press means, and tells your Mac "the letter A was pressed" over USB or Bluetooth.

Your Mac never sees which physical switch you pressed. It only sees what the firmware reports. So if you want the key under your left little finger to be Escape instead of Caps Lock, you change the firmware, not anything on the Mac. The change then follows the keyboard to any computer, phone or tablet you connect it to.

Three kinds of firmware

The app knows three firmware families. Which ones your keyboard can run depends on the keyboard.

FamilyKeyboardsWhat it is
ZMKImprint, Go60, Glove80The open-source firmware most wireless keyboards run, and the one most of this guide is written around. It is very capable, but normally configured by editing text files in a programmer's notation and running developer tools. The app does that part for you. The two MoErgo boards run MoErgo's own version of ZMK.
RMKImprint, Go60, Glove80A newer firmware written in Rust. On the MoErgo boards and the Imprint the app offers a community version, moergo-rmk by colonelpanic, with animated lighting and bilateral home-row mods, which is configured on the running keyboard. The Imprint can also build plain RMK. Both are experimental.
DygmaDefyDygma's own firmware, which stays on the keyboard. The app writes your layout to it over USB; nothing is built.

Within a family, the firmwares the app offers differ in what they can do, and the app shows only what the chosen firmware supports. A keyboard's firmware is chosen on its board's page (Chapter 12).

The keymap: what each key does

The heart of your configuration is the keymap: a list saying, for every key, what it does. What a key does is called its binding. The simplest binding is "press a key", for example "send the letter A". In ZMK's own notation that is written &kp A. You never need to write this notation, but the app shows it, and it helps to recognize its shape: an ampersand, the name of a behavior (kp means "key press"), and then the details (A).

The app uses this one notation for every family. When a layout goes to RMK or Dygma firmware, the app translates each binding; what a firmware cannot express is flagged on the key, never dropped silently.

Behaviors: the kinds of thing a key can do

"Key press" is one behavior. There are many others. A few examples, each explained fully later:

Layers: several keyboards in one

A small keyboard has fewer keys than a laptop, yet it can do more, because of layers. A layer is a complete set of bindings, one for every key. Your keyboard has a base layer that is always active, and further layers stacked on top that you switch on when you need them.

You already use the idea: holding Shift turns your number row into a symbol row. A layer key works the same way, except that you decide what every key becomes. Hold a thumb key, and the keys under your right hand become arrow keys; let go, and they are letters again.

Two special bindings make layers work well together. A transparent key lets the layer beneath show through, so a layer only needs to define the keys it changes. A key set to none does nothing at all and blocks what is underneath.

Two halves

All four supported keyboards are split into a left and a right half. Each half has its own small computer and its own firmware. One half, the central or main half (the left one on all four), holds the keymap and talks to your Mac. The other, the peripheral, reports its key presses to the central half. This matters at one moment only: when you install new firmware, you install it on each half separately.

Building and flashing

ZMK cannot be changed while it runs in the way a phone app's settings can. Your design has to be turned into a new firmware file. That step is called a build, and it takes a few minutes on a server. Putting the finished file onto the keyboard is called flashing.

To be flashed, a half is put into its bootloader: a tiny built-in program that makes the half appear on your Mac as a USB drive. Copying the firmware file onto that drive installs it. The bootloader cannot be erased by flashing, which is why a bad layout can always be replaced with a good one.

Configured on the keyboard instead

Some firmware keeps the layout as data the keyboard can change while it runs. Then there is no build: the app connects over USB, saves a copy of what the keyboard holds, and writes only what differs. Your layout takes effect at once.

→
ApplyThe app writes it to the keyboard over USB.
→
TypeThe keyboard uses it at once.

This is how the Dygma Defy works, with the firmware Dygma ships, and how the MoErgo boards and the Imprint work on RMK for MoErgo, after that firmware has been flashed once. ZMK has a smaller version of the same idea, ZMK Studio, which can change what keys do on a running keyboard but nothing else; the app can use it on firmware built with Studio (Chapter 13).

Boards and layouts: where your work lives

The app keeps your work at two levels.

  • A board is one of your keyboards as the app knows it: which model it is, which firmware it runs, that firmware's settings, and the layouts you use with it. Your boards are listed on the welcome screen, My Boards, and kept by the app.
  • A layout is what the keys do: layers, bindings, behaviors, combos, per-key colors and pointing settings. A layout is a single file on your Mac ending in .kcproj, and a board can have any number of them, with one marked current.

Nothing about the firmware is kept in a layout, and changing a board never touches a layout file. The firmware configuration is generated from the two together each time you build, so you never edit configuration files by hand, and nothing is lost if you flash a different layout: make the layout current again and build.
