Key Tester

The Key Tester tab draws the board and lights each key as you press it on the keyboard, keeping count of the keys seen; Start Over clears the count. Presses are matched against the board's current layout, or the factory layout when there is none, so the tab says which. The computer only reports what a key sends, so a press lights every key of the layout that can send it, on any layer; keys that send nothing to the computer, such as layer keys, cannot be tested and are drawn hollow. Hold ⌘ to use the app's shortcuts while the tester has the keyboard.

Every key also plays a note, so the board becomes an instrument. Sound turns it on and off; Wave chooses a sine, triangle, sawtooth or square wave; Scale lays the notes out across the keys as chromatic, Wicki-Hayden, major, minor, pentatonic, minor pentatonic or blues; Volume and Transpose do what they say, and the range of notes is shown beside them. Clicking a key on the drawing plays it too. If the computer's sound output is not answering, the tester says so and keys still light up.

Advanced mode, in the editor

Two things that are part of a layout but rarely touched live in the editor's Advanced mode, which is offered for firmware built from ZMK's configuration files.

Layer rules

A layer rule turns one layer on automatically while a combination of others is active. ZMK calls these conditional layers. The classic use: you have a Lower layer on the left thumb and a Raise layer on the right; holding both gives you a third, Adjust, with no key of its own.

  1. Click New Rule.
  2. Under When all of these layers are on, choose the layers that must be active together.
  3. Under also turn on, choose the layer to switch on.

Custom devicetree

Two text boxes take anything the editor does not cover, written into the keymap file exactly as you type it, so they are for people following the ZMK documentation. Custom behaviors goes inside the keymap's behaviors section, and behaviors defined there appear in the picker's Custom tab; Custom devicetree goes at the end of the keymap file. Add-ons you have built in offer a starter for each box.

Chapter 13

Putting a layout on the keyboard

Getting your layout out of the app and into the keyboard: by building and flashing firmware, or by writing it to a keyboard that is configured while it runs.

Apply

Whatever the firmware, the first step is the same. In the editor, open the Apply mode and click Apply to Board. The layout is saved, becomes the board's current layout, and the app takes you to the board's page: to Build & Flash if the firmware is built, or to Keyboard if it is configured live. The board's firmware and settings are not changed.

Before that, the editor keeps checking the layout against the board's firmware. The status bar shows a count of problems, and Generated Files mode lists them under Problems; click one to go to the key or item it concerns.

  • Errors must be fixed; the files cannot be generated or written while any remain. Examples: a key that switches to a layer that no longer exists; a combo with only one key; brightness above the keyboard's limit; a key that uses something the firmware cannot express.
  • Warnings are advice; you can build anyway. Examples: no key enters the bootloader; per-key colors with no key to change the lighting effect; an LED order unconfirmed on hardware.

Below the problems, tabs show each file the app will produce. You never need to read them, but they are there if you are curious or are asking for help in the firmware's community. ZMK firmware is built from a .keymap (your layers, behaviors, combos, macros and lighting), a .conf (the board's settings), config/west.yml (which ZMK and add-ons to build from), build.yaml (one firmware file for each half) and a workflow that tells GitHub to do the build. Plain RMK is built from a generated Rust project: keyboard.toml, Cargo.toml, a source file for each half and the same kind of workflow. Firmware configured live has no files to show, so the Defy and the RMK for MoErgo boards have no Generated Files mode.

Build & Flash

For ZMK, and for plain RMK on the Imprint, a change takes three steps: the app generates configuration files from the board and its current layout, a build service builds firmware from them, and you flash that firmware onto each half.

The tab starts by saying exactly what it will build: the firmware, how many settings differ from the board's defaults, and the layout. Change any of them under Firmware, Settings and Layouts.

One-time set-up for building

The app builds firmware with GitHub Actions, a free service that compiles firmware on GitHub's computers. Nothing has to be installed for the build itself, but the app needs access to a GitHub account.

  1. Create a free account at github.com if you do not have one.
  2. Install the GitHub command-line tool. With Homebrew: brew install gh.
  3. In Terminal, run gh auth login and follow the prompts to sign in.

If you see "Not signed in to GitHub" in the app, this is the step that is missing.

Building

  1. Under Build the firmware, click Choose Folder…. For your first build, make a new empty folder, for example go60-firmware. The app creates a private repository on your GitHub account, named after the folder. Later, choose the same folder again; the app remembers it for the board.
  2. Click Build Firmware.

The app then reports what it is doing: pushing the configuration to GitHub, waiting for the build to start, building (with a running clock), and downloading the firmware. A first build takes several minutes; later ones are usually quicker. If the build fails, the app shows the end of GitHub's log and Open on GitHub shows the build in your browser.

When it finishes you see "Built 2 firmware file(s). Flash each half below." and the files appear in the flashing section.

If the firmware does not build

The cause is nearly always text typed by hand: a binding in the Binding box that ZMK does not accept, something in the editor's Advanced boxes, or a line under Extra settings. Look for the name of a key or behavior in the log, fix it and build again. An add-on can fail to build too; remove it and try again.

Building some other way

Export Firmware Config… (⌘E) writes the generated files into a folder of your choice, laid out as a standard ZMK configuration or RMK project, together with a copy of the layout. Use it if you already have your own firmware repository or build on your own computer.

Flashing

Each half of a split keyboard is a separate computer with its own firmware, so each is flashed separately. To accept new firmware, a half must be in its bootloader: a special mode in which it appears on your Mac as a small USB drive. Copying a firmware file onto that drive installs it; the half then restarts by itself and the drive disappears.

The app guides you through it, one half at a time, in the right order for your keyboard, and tells you how to enter the bootloader on it:

  1. Connect the half named in the first step to your Mac with a USB cable.
  2. Put it into its bootloader. The step tells you how for your keyboard; see also Chapter 15. The app is waiting for the drive and says "Bootloader found. Ready to flash." when it appears.
  3. Click Flash Left Half or Flash Right Half. The app checks that the file really is for this half of this keyboard before copying it. It then says "Flashed."
  4. Repeat for the other half.

When both are done, the halves restart and reconnect to each other. macOS may complain that a disk "was not ejected properly" when a half restarts. That is normal.

To flash firmware you obtained some other way, click Choose Firmware Files… and select the .uf2 files, one for each half. The app works out which is which; if it cannot, give the files names containing "left" and "right". Start Over resets the steps.

Flashing is safe, but be patient

The bootloader is separate from the firmware and is not replaced by flashing, so a bad build cannot lock you out: you can always enter the bootloader with the keyboard's reset button and flash again, including the manufacturer's original firmware. Do not unplug a half while it is being flashed.

Pairing after flashing

If the halves do not find each other afterward, or the keyboard will not reconnect to your computer, see Chapter 17. Usually a reset of both halves, or clearing the Bluetooth profile and pairing again, fixes it. Switching between firmware families loses the Bluetooth pairings: computers must pair again.

Updating ZMK directly (ZMK Studio)

ZMK Studio is a feature of ZMK that lets a program change key assignments on a running keyboard over USB, with no build and no flashing. The app can use it on firmware built with Studio: the standard ZMK firmware of all three ZMK boards. The controls are in the editor's Apply mode, under Update the keyboard directly.

  1. Connect the main half (the left half) by USB.
  2. Click Find Keyboard.
  3. If the app says the keyboard is locked, unlock it: on the Imprint, hold the A and F key positions on the left half together for three seconds; otherwise press a key assigned to Studio unlock. Then click Find Keyboard again.
  4. The app compares the keyboard with your layout and tells you how many keys differ. Click Send to Keyboard to update the keyboard, or Use the Keyboard's Keys Instead to copy the keyboard's current assignments into your layout.

What can be sent this way is limited to what keys do, using behaviors the firmware on the keyboard already has. The app tells you when some differences "need a firmware build". These always need a build and a flash:

  • new or changed behaviors, combos and macros;
  • more layers than the firmware has room for (see "Spare layers" in Chapter 6);
  • lighting, pointing and anything in the board's settings.

The app also refuses to send to a keyboard that is saved as a different board, or is not the device this board is linked to, and says which board it belongs to.

A practical rhythm

Build and flash once with your behaviors, combos and a few spare layers in place. After that, day-to-day changes to which key does what can go over ZMK Studio in seconds. Build again when you change something structural.

The per-key lighting firmwares do not offer ZMK Studio, and neither does RMK. Direct updates currently work over USB only.

Chapter 14

Importing an existing layout

Bring in a layout you already have instead of starting again.

Choose Import a Keymap… on a board's Layouts tab, or File › Import Keymap… (⌘I). The app opens the result as a new, unsaved layout and leaves the original file untouched.

You haveWhat to choose
A ZMK configuration you or someone else wroteThe .keymap file. If a .conf file with the same name sits beside it, its settings are read too.
A Go60 or Glove80 layout made in MoErgo's Layout EditorEither file the Layout Editor gives you: the .keymap file it offers for download, or the layout exported as a JSON file.
An RMK configuration, such as TailorKey for RMKThe .toml file, the form moergo-rmk keeps a layout in.

The app works out which keyboard the file is for from its name, its contents and the number of keys. If several of your boards could use it, it asks which; if none of your boards is that keyboard, it offers to add one and open the layout under it.

What comes across

  • Layers and their names, and every key assignment.
  • Hold-taps, tap-dances, mod-morphs, sticky keys and macros, which become editable behaviors.
  • The description written above a behavior, when the file has one.
  • Combos and layer rules.
  • Trackball and touchpad settings, mouse-key speeds, and their different settings on particular layers (Chapter 10).
  • Per-key colors, from files that have them.

Firmware settings found in the file belong to the board, not the layout, so the app asks: Apply to Board replaces the board's own values for those settings; Ignore leaves the board as it is. Settings the app does not know are kept as extra settings.

After importing, the app shows a short summary: how many layers, behaviors and combos were read, and anything it could not fully understand.

Files that build their contents with ZMK's helper macros, or include parts only under a condition (#ifdef), are read the way the firmware build would read them. If a file chooses by a name the app does not know, the summary says so and that part is left out, as a build would leave it out.

What is kept as it is

Hand-written ZMK files can contain almost anything. Whatever the app cannot turn into something editable is not thrown away. It is kept as text in the editor's Advanced mode and written back out unchanged when you build. A binding the app does not recognize shows on its key as raw text and still works.

Check before you flash

Look through each layer after importing, and open Generated Files to see whether any problems are listed. In particular, make sure the system layer still has its Bluetooth and bootloader keys.

Chapter 16

Recipes

Seven worked examples, each from start to finish. They assume a new layout started from the factory template.

1. Caps Lock that is Escape when tapped, Control when held

For: anyone who uses Control or Escape a lot. Uses: the inspector.

  1. On the base layer, select the key in the Caps Lock position.
  2. In the picker, search esc and click Esc.
  3. In the inspector, under When held, click ⌃.

The keycap shows Esc with a small ⌃. Tap it for Escape; hold it with another key for Control.

2. Arrow keys under your right hand

For: moving the cursor without leaving the home row. Uses: layers.

  1. Add Layer; rename it Nav.
  2. On Nav, assign ← ↓ ↑ → to the H, J, K and L positions (or J, K, I, L for an inverted T). Add Home, End, Page Up and Page Down nearby.
  3. On the base layer, select a left thumb key and, in the Layers tab, click mo Nav. Or keep the key's tap: select Space and choose Nav under When held.

3. A number pad on a toggle

For: entering lots of numbers. Uses: layers, toggle.

  1. Add a layer named Numpad. Under the right hand, lay out 7 8 9 / 4 5 6 / 1 2 3 with 0 on a thumb key, using the Keypad or Basic tab. Add ., +, - and Enter around them.
  2. On the base layer, assign tog Numpad to a spare key.
  3. On Numpad, assign tog Numpad to the same key, so the key that turned the layer on also turns it off.

4. Home-row mods

For: shortcuts without reaching. Uses: Behaviors.

  1. In Behaviors mode, click Left hand and Right hand under Home-row mods.
  2. In Keyboard mode, set the left home row through the Binding box: &hml LCTRL A, &hml LALT S, &hml LGUI D, &hml LSHFT F.
  3. Mirror it on the right: &hmr RSHFT J, &hmr RGUI K, &hmr RALT L, &hmr RCTRL SEMI.
  4. Apply, build, flash, and type normally for a day before changing any timing. Then tune by symptom (Chapter 8).

5. A combo for Escape and one for Caps Word

Uses: Combos.

  1. In Combos mode, New Combo; click J and K; set the binding to Esc.
  2. New Combo again; click the two keys under your index fingers, F and J; set the binding to Caps word.
  3. Turn on Only after a pause in typing for both if they fire by accident.

6. A macro that types your email address

Uses: Behaviors, macro.

  1. In Behaviors mode, click Macro. Name it "Email".
  2. In Type text, type your address and press Return. The steps fill in.
  3. In Keyboard mode, pick a key on a layer you do not hit by accident and assign Email from the Custom tab.

7. Layers you can see

For: learning a new layout. Uses: per-key lighting (experimental).

  1. On the board's page, under Firmware, choose a firmware with per-key lighting (Chapter 11). Open the layout; Lighting mode is now in the mode bar.
  2. On the base layer, choose a dim, calm color and click Fill.
  3. On each other layer, click Color by what keys do, then repaint anything you want to stand out.
  4. On a ZMK per-key firmware, make sure a key somewhere is RGB EFF. Apply, then build and flash, or on RMK for MoErgo apply to the keyboard. On the ZMK branch, press RGB EFF until the colors appear.

TermMeaning
Add-onA community extra built into a ZMK firmware, chosen on the board's Firmware tab.

BehaviorZMK's word for anything a key can do.
BindingA behavior assigned to one key on one layer, with its details: "send A", "hold for layer Nav".
BoardOne of your keyboards as the app knows it: model, firmware, settings, layouts. Listed in My Boards.

Central / main halfThe half of a split keyboard that talks to the computer.
ComboTwo or more keys pressed together to produce something else.
Conditional layerA layer that turns on when certain others are on. The app calls it a layer rule.
Current layoutThe one of a board's layouts that is built into its firmware or written to the keyboard.
DebounceIgnoring the electrical flicker of a switch so one press counts once.
FamilyA kind of firmware: ZMK, RMK or Dygma. Firmwares within a family differ in what they can do.
FirmwareThe program that runs inside the keyboard.
FlashTo install firmware on the keyboard.
GuiThe Command key on a Mac; the Windows key on a PC.
Hold-tapA key that does one thing held and another tapped. Mod-tap and layer-tap are kinds of hold-tap.
Home-row modsModifiers placed on the home-row letter keys as hold-taps.
KeymapThe complete set of layers and bindings; also the file ZMK reads them from.
LayerOne complete set of key assignments. Several can be active, stacked.
LayoutWhat the keys do, saved as a .kcproj file: layers, behaviors, combos, colors, pointing.
Live configurationWriting a layout to a running keyboard over USB, with no build: the Defy, and RMK for MoErgo.
MacroA recorded sequence of key actions played by one key.
Mod-morphA key that changes what it sends while a modifier is held.

moergo-rmkcolonelpanic's community RMK firmware for MoErgo's boards, and the base of the Imprint's RMK fork. "RMK for MoErgo" in the app.

ProfileOne remembered Bluetooth device.
